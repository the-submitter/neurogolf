# Increase the repository gate deadline to 600 seconds

Status: independently reviewed, explicitly authorized, and implemented on
2026-07-14. The review recommended the scoped change and the integrity manifest
was intentionally refreshed.

## Requested change

Increase the default repository acceptance-gate deadline from 120 seconds to
600 seconds in `configs/solver.yaml` and the `GateConfig` fallback. Update the
bootstrap example and configuration regression test to match.

The deadline remains one global, enforced gate deadline. This request does not
remove timeout checks, add an override, reduce any suite, or change promotion
eligibility.

## Reproduction and evidence

1. `utils/neurogolf_utils.py::score_network` computes memory and parameter
   counts and contains no deadline or 120-second requirement.
2. `utils/neurogolf_utils.py::verify_network` and `verify_subset` execute and
   score examples without a wall-clock cutoff.
3. `configs/solver.yaml` independently defines `gate.timeout_seconds: 120`.
4. `AcceptanceGate.run` constructs a repository deadline from that setting and
   uses it across generation, correctness suites, and the later official score.
5. `OfficialAdapter.score_model` accepts `deadline=None`; only the repository
   gate supplies the global deadline. The deadline is therefore orchestration,
   not part of the official objective or points calculation.
6. A fully correct task 001 candidate previously reached the sealed suite with
   no semantic failures but timed out under load. The exact unchanged hash later
   passed 3148/3148 cases and official scoring in 80.43 seconds when contention
   cleared, demonstrating that the 120-second cutoff can create infrastructure
   false negatives without distinguishing graph correctness or score.

## Scope and scorer-parity impact

The proposed value gives the complete existing gate more time to finish. All
public, provided ARC-GEN, regression, fuzz, boundary, and sealed cases remain
mandatory, legality and integrity remain mandatory, and official scoring is
unchanged:

```text
objective = intermediate tensor bytes + parameter elements
points = max(1, 25 - log(max(1, objective)))
```

This aligns repository acceptance more closely with the immutable scorer by
avoiding a local 120-second limit that the scorer does not define. It does relax
the repository's resource ceiling from 120 to 600 seconds, so the new limit must
remain explicit and enforced.

## Independent review outcome

The reviewer confirmed that the 120-second value is repository orchestration,
not part of the immutable metric utility, and recommended approval. The change
retains one enforced global deadline and does not alter legality, suite
membership or requiredness, output comparison, objective, points,
score-nonregression, or promotion rules. It affects future gates for all 400
tasks; the operational tradeoff is that a contended gate may occupy a worker
for up to five times longer. Existing gate results and champions need no
migration because a pass under 120 seconds also satisfies the 600-second limit.
